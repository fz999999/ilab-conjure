# iLab CONJURE 单密码登录设计

## 目标
将公网入口从浏览器原生的 Nginx Basic Auth 改为网站内单密码登录，只显示一个密码输入框。密码由服务器环境变量注入，代码仓库不保存明文。

## 已确认现状
- 公网入口由 Nginx 监听 HTTPS 8443，并通过 `auth_basic` 保护 `/`。
- Nginx 将请求转发到 `127.0.0.1:8787` 的 FastAPI WebUI。
- WebUI 当前没有公网访问认证中间件。

## 方案
1. 在 FastAPI 增加可选访问门禁中间件；配置存在时保护主页面、API、静态文件、输入输出文件和 SSE。
2. `/login` 提供内联登录页，只包含密码输入框；密码错误返回 401。
3. 使用 PBKDF2-HMAC-SHA256 密码哈希校验，不在仓库中写入明文密码。
4. 登录成功后签发 HMAC 签名、HttpOnly、Secure、SameSite=Lax 的 30 天 Cookie。
5. 使用内存中的按 IP 失败次数限制，5 分钟最多 5 次失败，成功后清除记录。
6. `/logout` 清除 Cookie；主界面顶部增加退出按钮。
7. Nginx 删除 `auth_basic` 与 `auth_basic_user_file`，保留 HTTPS 和反向代理。

## 边界
- 现有本地开发和测试在没有访问门禁环境变量时保持不变。
- API 未认证请求返回 JSON 401；浏览器页面请求重定向到 `/login`。
- `next` 只允许站内绝对路径，拒绝外部跳转。
- 生产配置只保存哈希和会话签名密钥，明文密码仅用于生成哈希时输入。

## 验收标准
- 未登录访问公网 `/` 显示单密码登录页，不出现用户名输入框。
- 密码错误不能进入 WebUI。
- 密码正确后能进入 `/`，并能正常加载 API、静态资源和余额查询。
- `/logout` 后再次访问 `/` 回到登录页。
- Nginx 配置检查通过，服务重启后仍为 running。
